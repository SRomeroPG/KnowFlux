# ADR-0001 — Single-vendor Claude strike team

**Status**: Accepted 2026-10-09

## Context
The project used a two-vendor model: Codex as Implementation Lead (`AGENTS.md`, `.codex/`, `.prompts/codex/`) and Claude as independent Audit Orchestrator (`CLAUDE.md`, `AI_STRIKE_TEAM_BOOTSTRAP.md`). Hand-offs between vendors, plus blocking on every spec gap, stalled P002.

## Decision
- The Codex implementation role is retired. `AGENTS.md`, `.codex/`, `.prompts/codex/` and `.strike-team/AI_STRIKE_TEAM_BOOTSTRAP.md` are kept frozen as history and are no longer operating instructions.
- `.strike-team/PROTOCOL_V2.md` is the operating protocol.
- The root Claude session is the Foreman (skill `/knowflux-foreman`). It orchestrates Claude implementer agents and Claude auditor agents.
- Independence is preserved by enforced role separation instead of vendor separation: implementer and auditor are separate agent instances; audit passes are blind (the auditor does not receive the implementer's claims); conformance expectations are written independently of the implementation; CRITICAL phases get Opus adjudication.

## Consequences
- One vendor, one tool surface, no cross-vendor hand-off latency.
- Independence now depends on the protocol being followed; the Foreman must not implement and audit the same change in one agent context.
- Historical artifacts (P001 audits, the P002 blocked hand-off) remain valid records and are not rewritten.
